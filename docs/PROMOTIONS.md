# 节日充值活动

在 **`config.local.yaml`** 配置一个全局活动；固定档位、自定义金额、易支付和所有已启用的 USDT 网络均适用。修改后需要重新加载服务，活动开始/结束本身不需要重启。

## 示例：限时九折

```yaml
promotion:
  enabled: true
  mode: discount
  percent: 10
  start_at: "2026-10-01 00:00:00"
  end_at: "2026-10-07 23:59:59"
```

`percent: 10` 表示**减免 10%（九折）**：选 100 元，付 90 元，到账 100 元。
切换到 `mode: gift`，同样的比例表示付 100 元、送 10 元、到账 110 元。两种模式互斥，不叠加。
仓库模板默认 `enabled: false`；示例日期和比例不代表已启用线上活动。

可配合活动使用文案：

> 🎉 节日限时充值优惠：充值立减 10%！100 元余额仅需支付 90 元。
> 活动时间：2026 年 10 月 1 日 00:00:00 至 10 月 7 日 23:59:59（上海时间）。固定档位与自定义金额均可参加，优惠以下单时为准。

## 配置与时间规则

- `mode` 取 `discount` 或 `gift`。旧配置省略此字段时按 `gift` 处理，保留旧赠送活动语义。
- `percent` 支持小数，必须是有限非负数；折扣模式必须小于 100，0 表示没有优惠。
- 时间支持 `YYYY-MM-DD HH:MM:SS`（固定按 `Asia/Shanghai`，不受服务器时区影响），或带时区的 RFC3339，如 `2026-10-01T00:00:00+08:00`。
- 起止边界均包含，精确到配置指定的时刻。若写 `23:59:59`，该时刻之后即为结束。
- 一端留空表示该侧不限制；两端留空表示启用期间一直有效。格式错误、未知模式、负数/非有限比例、倒置时间都会阻止启动，即使活动当前关闭也需修正错误字段。
- 下单前统一计算并锁定优惠。活动结束、关闭、更换模式、修改比例或服务重启，均不重新计算已有订单；支付仍须遵守订单本身及支付网关的有效期。
- 已显示在 Telegram 的消息不会主动编辑；用户刷新菜单或点击旧按钮时按当时配置判断，最终以新建订单的金额为准。

金额以人民币“分”为粒度，按十进制四舍五入：折扣模式先舍入应付金额，减免额 = 面额 − 应付；赠送模式先舍入赠额，再加到面额。例：19.99 元打五折应付 10.00 元。折后不足 0.01 元的订单拒绝创建，不会免费下单。USDT 以折后人民币金额交由网关换算，用户必须支付返回的精确 USDT 数额。

## 订单、入账与兼容

| 字段 | 含义 |
| --- | --- |
| `amount` | 用户选择的原始充值面额（CNY），保留旧字段语义 |
| `gift_amount` | 本单赠额（CNY） |
| `discount_amount` | 本单减免额（CNY），旧订单默认为 0 |
| `promotion_mode` / `promotion_percent` | 下单时的模式和百分比快照 |
| `pay_amount` / `pay_currency` | 支付渠道返回的应付金额与币种（CNY / USDT） |

sub2api 的 `amount` = 面额 + 赠额；`base_amount` = 面额 − 减免额。邀请返利始终基于人民币实付基数，不包含赠额，不能用 USDT 数额替代。

启动时 GORM AutoMigrate 增加快照列；手动迁移使用 `migrations/002_promotion_snapshot.sql`（可重复执行）。已有订单不重算金额，旧赠送订单的 `gift_amount` 继续有效。无需修改 sub2api 请求结构。

## 部署与验证

1. 在 `config.local.yaml` 配置模式、比例和时间，保留原有凭据；`.env` 中的数据库密码必须与 DSN 一致。
2. 在部署时执行 `docker compose up -d --build telegram-shop`，加载新代码和本地配置。首次从旧版升级时会重建应用容器并切换为挂载 `config.local.yaml`。只改变配置时也建议用该命令，避免编辑器替换文件 inode 后旧挂载仍读取旧内容。
3. 查看配置启动错误及 `/health`，检查中英文菜单；下单日志含 `payable_cny`、`credit_amount` 和 `promotion_mode`，便于核对实付/到账口径。

本地测试（Go 1.23+）：

```bash
go test ./...
go vet ./...
```

订单/迁移集成测试仅在设置 `TEST_DATABASE_DSN` 时运行，必须指向**独立测试 PostgreSQL** 的 URL。测试创建随机 schema 并在结束时删除该 schema；从不读取 `config.local.yaml`。

```bash
TEST_DATABASE_DSN='postgres://test:test@127.0.0.1:5432/test?sslmode=disable' go test ./internal/service -count=1
```

覆盖折扣/赠送、固定/自定义金额、上海时区边界、旧配置、舍入、无效金额、CNY/USDT 下单、付款后回调失败与补单、重复回调、历史订单和数据库迁移。支付和 sub2api HTTP 测试使用本地模拟服务，不产生真实支付或余额入账。
